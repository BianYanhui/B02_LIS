# P0-A3 下一轮

判定 **Case A**。Q8 选 **D**：收窄普遍拥塞的 motivation。

单卡上直接观测到的新 block 大约 124 /s，前缀覆盖变化大约 1.9 /s，和 wrapper 的一次完成一条相同。热命中不再改变前缀覆盖，wrapper 仍会发一条。对 9408 frame/s 的 ρ，block 级是 0.013，前缀级是 0.0002。10 ms 里最大的一步有 129 个 block hash，大约 14 ms 排空，没有持续队列。

不选 A。官方 `BlockStored` / `BlockRemoved` 已经能用，观测缺口不是下一步的瓶颈。

不选 B。四卡同时的速率没有测，但单卡前缀级只有大约 2 条/s。把 block 级乘 4 也只是大约 500 frame/s 的外推，ρ 约 0.05。不值得为这个数开 replay。

不选 C。64 GPU 会把问题从“这四张卡的自然负载”换成另一次规模外推。本轮没有给出必须上到那个规模的调度相关速率。

下一轮不做实验。如果改论文，把控制面问题写成给定预算下的协调：冷的前缀需要一条覆盖广告，热的重复不需要再广告，缓存打满后的 `BlockRemoved` 是真实驱逐，但在这张 T4 上是每秒十几条而不是每秒近万条。不要把 353 block/s 或 124 block/s 写成已经发出的控制消息。
