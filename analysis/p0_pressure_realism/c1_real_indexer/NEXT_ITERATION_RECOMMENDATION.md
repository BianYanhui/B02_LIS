# P0-C1 之后

按 **Case 1** 停。不要把索引拥塞写成动机，也不要为了得到一个瓶颈继续加大回放倍数。

测到的事实：

- 单张 T4 上这份负载的原生 msgpack 大约 38 kbit/s。Case 1 那句「网络负载较大」不成立。
- Dynamo 0.10 这套索引器，debug 构建，64 倍循环回放仍是 256 事件/s、积压 0。`NO_BOTTLENECK_OBSERVED`。
- 块级外部 hash 和 `/dump` 一致，6525 对 6525。一条从根开始的前缀查询命中 1040/1040。
- 前缀广告能把 6615 次 hash 收成 102 条记录，但有一次部分驱逐留下 448 token。那种压缩丢掉了这段祖先的可见性，不能当成无损方案去实现。

不要做：

- Dynamo 和 KVSelect 的正式集成
- 64 GPU，或 1024/4096 worker replay
- 为了制造 ρ≥1 去限速
- 端到端 TTFT 矩阵

论文若改动机，只写已经测到的两层：原生块事件存在，前缀级广告少得多；两者在这台机器的这份负载上都远低于 10 Mbit 路径的排空能力。索引器处理这些事件没有形成排队。
